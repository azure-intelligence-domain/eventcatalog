## Overview

The integration platform carries every hand-off between the business domains. No point-to-point
shortcuts: if two systems exchange something, the platform sees it. That is what makes the
Intelligence domain possible later.

It is built API-led:

```mermaid
flowchart TB
    consumers(["Consumers"]) --> apim{{"API Management"}}
    apim --> experience["Experience APIs"]
    experience --> process["Process APIs"]
    process -- "publish" --> events[["Event Grid → Service Bus queue per subscriber"]]
    events -- "subscribe" --> process
    process --> system["System APIs"]
    system --> backends[("Source systems")]
```

## What the platform guarantees

| Guarantee | How |
|---|---|
| Every event carries its context | The <Link href="/docs/custom/platform/01-the-envelope">envelope</Link>: CloudEvents + `correlationid` + business keys |
| Every interface has a contract | OpenAPI and AsyncAPI, checked against the <Link href="/docs/custom/platform/02-contracts-and-rules">adidas API guidelines</Link> |
| No breaking changes | The contract check compares every change with the last release |
| Everything is cataloged | Released contracts appear here automatically (<Link href="/docs/custom/platform/03-add-your-service">how</Link>) |

## Data model

The platform has no business data of its own: it carries events. Every event has the same envelope, and its business keys point into the domains' models. That is what lets the Intelligence domain join the facts of every domain into one story.
